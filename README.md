# Greeting MCP Server

## Overview

This project is a simple Model Context Protocol (MCP) server built with Node.js, TypeScript, the official MCP TypeScript SDK, Zod, and stdio transport.

It exposes two tools, `greet` and `introduce_me`, both validated with Zod and served over stdio. The project is designed as a training example for learning how to build and run a basic MCP server locally.

## Features

- MCP server built with the official TypeScript SDK
- Stdio transport for local MCP clients and MCP Inspector
- Zod-based input validation for tool requests
- Clear tool descriptions and structured text responses
- No use of `console.log()` so stdio communication stays clean

## Prerequisites

Before you start, install the following tools:

- [Node.js](https://nodejs.org/) 18 or later
- `npm`, which is included with Node.js
- A terminal or PowerShell session
- MCP Inspector is downloaded on demand by the repository script, so no separate global install is required

No environment variables are required for the current version of the project.

## Installation and Setup

1. Clone the repository.

   ```powershell
   git clone https://github.com/RawandBawatneh/mcp-training.git
   ```

2. Navigate to the project directory.

   ```powershell
   cd mcp-training\week-01\todo-mcp-server
   ```

3. Install the dependencies.

   ```powershell
   npm install
   ```

4. Build the project.

   ```powershell
   npm run build
   ```

   This compiles the TypeScript source into `dist/index.js`.

5. Run the server or open it in MCP Inspector.

   Use `npm start` to launch the compiled server, or use `npm run inspect` to build the project and open it with MCP Inspector.

## How to Run

Start the compiled MCP server:

```powershell
npm run build
npm start
```

Run the project with MCP Inspector for manual testing:

```powershell
npm run inspect
```

There is no separate automated test script in this repository. The supported way to test the server is through MCP Inspector using the `inspect` script.

## Usage

The server currently provides two tools:

### `greet`

Input schema:

- `name`: Required string.
- Empty strings are rejected.
- Non-string values are rejected.

Example input:

```json
{
  "name": "Ahmed"
}
```

Example output:

```text
Hello, Rawand Bawatneh!
```

### `introduce_me`

Input schema:

- `name`: Required string.
- Empty strings are rejected.
- Non-string values are rejected.

Example input:

```json
{
  "name": "Ahmed"
}
```

Example output:

```text
Hello Ahmed! This MCP server was created by Rawand Bawatneh.
```

The `greet` tool always returns Rawand Bawatneh’s full name in the response, while `introduce_me` echoes the submitted name and mentions the server creator.

## Project Structure

- `package.json` defines the scripts, dependencies, and project metadata.
- `tsconfig.json` configures TypeScript compilation and output to `dist/`.
- `src/index.ts` contains the MCP server, tool registration, validation, and startup logic.
- `dist/` is generated by the build and contains the compiled JavaScript output.
- `package-lock.json` records the exact dependency versions installed by npm.

## Troubleshooting

- If `npm start` fails with a missing file error, run `npm run build` first so `dist/index.js` exists.
- If `npm run inspect` fails to start, make sure your machine can download packages through `npx`, because MCP Inspector is fetched automatically the first time it runs.
- If the tool returns a validation error, check that `name` is present, is a string, and is not empty after trimming.
- If nothing appears in the inspector, confirm that you are running the script from `week-01/todo-mcp-server` and that the server was built successfully.

## MCP Inspector Command

Launch MCP Inspector with:

```powershell
npm run inspect
```

That script runs `npm run build` and then starts Inspector with `npx -y @modelcontextprotocol/inspector node dist/index.js`.
